# Task: Practical exercise of Grade B

## Team
- Gustavo Deves Bueno
- Leonardo Trevisol  
- Pedro Henrique Bassani

## Prerequisites and Dependencies

- You need access to Visual Studio Code and the C/C++ Extension Pack.
- Recommended for Windows. (Not yet tested on Linux or Mac)

## General Comments

- The Objective:

  The objective of this project is to develop a C++ system using advanced concepts of Object-Oriented Programming, with special focus on the correct modeling of classes and their relationships.
Different types of relationships must be explored (dependency, generalization, association), with emphasis on simple and multilevel inheritance and the use of polymorphism.
<br>

- The Description:

  Groups are free to choose the theme of the system they want to develop.
The system must be a console application (text-based) that contains navigable menus for interacting with its features.
The UML Class Diagram is a mandatory part of the submission and will be used as an essential component in the evaluation, demonstrating planning and structuring before implementation.
Regardless of the chosen theme, the project must meet all technical requirements listed below.

<br>

- Technical Requirements (Checklist):

  (1) Modeling (UML Class Diagram)
  
  The group must deliver a UML diagram representing all classes, attributes, methods, and — most importantly — all system relationships (inheritance, association, etc.).
  <br>
  <br>
  (2) Simple Inheritance
  
  The system must include at least one simple inheritance hierarchy.

  Example: Item → Pocao.
  <br>
  <br>
  (3) Multilevel Inheritance

  The system must include at least one multilevel inheritance chain (minimum of 3 levels).

  Example: Personagem → Mago → MagoDeFogo.
  <br>
  <br>
  (4) Abstract Class and Virtual Methods

  The system must contain at least one abstract class (interface).

  This class must declare at least one pure virtual method (virtual void atacar() = 0).
  <br>
  <br>
  (5) Polymorphism

  The system must demonstrate polymorphism through overridden virtual methods in derived classes.

  Example:
  The method atacar() must have different implementations in Guerreiro and Mago.
  <br>
  <br>
  (6) Dynamic Allocation
  
  The system must use dynamic memory handling (pointers, new/delete) to manage objects.
  <br>
  <br>
  (7) Data Persistence

  The system must load and save its state (characters, items, inventory, etc.) using text files (.csv).
  <br>
  <br>
  (8) Method Overloading

  The system must include at least one example of method overloading (same method name with different parameter lists).
  
  <br>
  <br>

## Comentários gerais

- O Objetivo:

Desenvolver um sistema em C++ utilizando conceitos avançados de POO estudados na disciplina, com foco especial na modelagem das classes e seus relacionamentos.
Devem ser explorados diferentes tipos de relacionamentos (dependência, generalização e associação), com foco em herança simples e multível, além do uso de polimorfismo.

<br>

- A Descrição:

Os grupos têm liberdade para escolher o tema do sistema.
O sistema deve ser uma aplicação de console (modo texto) com menus navegáveis para interação.

A Modelagem UML é obrigatória e compõe parte fundamental da avaliação.
Independente do tema escolhido, o projeto deve atender todos os requisitos técnicos a seguir.

<br>

- Requisitos Técnicos (Checklist):
  (1) Modelagem (Diagrama de Classes UML)
  
  Representar todas as classes, atributos, métodos e, principalmente, os relacionamentos (herança, associação etc.).
  <br>
  (2) Herança Simples
  
  O sistema deve possuir pelo menos uma hierarquia simples de herança.

  Exemplo: Item → Poção.
  <br>
  <br>
  (3) Herança Multinível

  O sistema deve conter uma hierarquia com no mínimo 3 níveis.

  Exemplo: Personagem → Mago → MagoDeFogo.
  <br>
  <br>
  (4) Classe Abstrata e Métodos Virtuais

  Pelo menos uma classe abstrata com métodos virtuais puros (virtual void atacar() = 0;).
  <br>
  <br>
  (5) Polimorfismo

  Demonstração de polimorfismo por meio de sobrescrita de métodos virtuais nas classes derivadas.

  <br>
  <br>
  (6) Alocação Dinâmica
  
  Uso obrigatório de new/delete, ponteiros ou gerenciamento dinâmico de objetos.
  <br>
  <br>
  (7) Persistência de Dados

  Salvar e carregar dados usando arquivos de texto como .csv.
  <br>
  <br>
  (8) Sobrecarga de Métodos (Overloading)

  Pelo menos um exemplo de métodos sobrecarregados (assinaturas diferentes).
  
  <br>
  <br>
